## Summary

Refactor the popular items windowed analytics into a multi-stage filter pipeline using asyncio queues for inter-stage communication. The system will decompose the computation into four independent filters (IngestFilter, AggregationFilter, RankingFilter, OutputFilter) that run concurrently. The pipeline maintains correctness of windowed ranking while enabling natural concurrent processing and improved code organization.

**Technical Approach**: Use asyncio queues to connect filters with streaming communication and sentinel values for end-of-stream signaling. Filters process data independently and concurrently via asyncio.gather(), enabling overlapping computation and natural decomposition of the analytics workflow.

## Technical Context

**Language/Version**: Python 3.11

**Primary Dependencies**: FastAPI, SQLAlchemy (asyncio), asyncpg, orjson

**Storage**: PostgreSQL 17 with asyncio driver (asyncpg)

**Testing**: pytest with asyncio support (pytest-asyncio)

**Target Platform**: Linux server (self-checkout backend service)

**Project Type**: Web service (FastAPI REST API)

**Performance Goals**: Complete analytics recompute within request timeout window; handle 100+ concurrent stations without blocking request processing

**Constraints**: Off-critical-path execution (background task); must not block request handlers; maintain identical ranking correctness to synchronous implementation

**Scale/Scope**: Single analytics pipeline recompute; window size ~1000 scans; ranking depth 200 items; catalog size 2000 items
